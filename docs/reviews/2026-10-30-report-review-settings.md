# Report review diagnostics, Detail and personal Sleep Goal

Report observations now include server-derived `browse_issues` with a stable code, scope (`browse` or `chart`) and message. Unrecognized mappings or incompatible units that prevent metric resolution are shown beside the result, including pending rows. Mapped results with missing/unsupported units or numeric overflow are explicitly identified as historical-only rather than falsely claiming they cannot appear in Browse. Missing/invalid collection dates and absent values also explain why plotting is unavailable. Normal qualitative results such as blood groups or positive/negative results are not reported as failed OCR solely because they lack a numeric point. Diagnostics are recomputed from stored originals on read and after review; correcting a unit clears the warning without another OCR pass.

The main Health Report shows pending and confirmed results and its existing actions. Page processing, Document evidence and Original OCR output are nested under Detail. Rejected results remain accessible in Detail for review instead of disappearing from the archive.

Sleep Goal moved from Customize overview to Settings → Personal settings. Its shared editor uses separate hour and minute selectors, supports an unset goal and 1–1440 minutes, and preserves existing saved targets. Saves use the existing per-user preference/version contract and preserve favorites, aliases and priorities. Each control saves immediately as requested. Both Sleep Goal and Customize Overview share one automatic-save form with serialized writes, authoritative responses, failure rollback and a Back button. There is no Save/Cancel workflow. Overview receives the model's saved preference response without reloading its summary or losing scroll state.

Regression coverage includes pending-result diagnostics, Browse-vs-chart distinction, qualitative results, warning removal after correction, the nested Detail UI, and personal goal selection/automatic save/reopen/Back. The diagnostic fixtures contain synthetic values only.

Android emulator coverage caught a native bridge abort when enabling the goal: `ClosedRange<Int>.Index` could not cast to `Int` in SkipFuseUI `ForEach`. Hour/minute options now use materialized arrays, whose integer indices are supported by the bridge. The end-to-end goal toggle/save/Back scenario covers this failure rather than relying on compilation alone.

Settings combines URL, username, password, admin user management and sign-out under Account. Processing/unlock/clear-device explanation rows are removed, export is titled Export, and the biometric control remains available under Security. Sleep Goal has no explanation row.

Release validation: backend 201 tests passed (2 existing ignored); portable Swift core 50 tests passed; iOS simulator report/Detail/personal settings end-to-end passed. Android ARM64 build, unit tests, lint and native-method verification passed. Emulator end-to-end verifies report diagnostics, nested Detail, Settings grouping, immediate favorite and hour/minute persistence, failed-write rollback, Back and reopen. Synthetic fixture resets retain monotonically increasing preference versions to avoid stale cache conflicts across repeated runs. Released as iOS 72 / Android 19; NAS API image `longlivehealth-backend-api:settings-auto-20261030` bundles the APK.
